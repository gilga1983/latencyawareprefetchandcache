# A2 latency-aware port

Source of truth: `gilga1983/rankmap-cache`, `projects/joint_cache_prefetch/make_elastic_a1_driver.py` plus the live RAP elastic allocator generated by `make_elastic_rap_driver.py`.

A2 semantics to preserve:

- one shared byte capacity M with disjoint reactive cache C and prefetch buffer P;
- work-conserving ElasticDualLRU: protected C/P quotas may borrow unused physical capacity;
- a demand hit in P consumes/removes the P entry and promotes it into C;
- RAP predictions are offered to P and are never simultaneously resident in C and P;
- Map maintains separate byte-rank stacks for demand LRU and observed RAP predictions;
- ten candidate protected splits `(C=M-P,P)` are scored each epoch;
- A2 objective is `reactive_hits + residual_prefetch_hits`;
- epoch adaptation changes protected quota only; existing payload is not forcibly flushed;
- first epoch starts all-cache (`C=M,P=0`).

Latency port requirements:

1. Preserve the above policy decisions exactly at backend latency 0.
2. Add in-flight state orthogonally to A2 policy state.
3. Classify demand service as resident-C hit, resident-P hit, delayed/coalesced demand, or new demand I/O.
4. A P prediction that has been issued but has not completed is in-flight, not resident P. A demand for it coalesces with the outstanding fetch and waits only the remaining latency.
5. Completion inserts the object into P only if the prediction has not already been consumed/coalesced by demand and subject to the live A2 entitlement/reclaim semantics.
6. Keep the original A2 Map hit-count objective for the baseline. A later LA-A2 variant will change only the candidate scoring objective to latency saved.

Validation gates:

- unit tests for C/P disjointness, P-hit promotion, borrowing/reclaim, and delayed P hit;
- zero-latency equivalence against source A2 on an identical trace prefix and byte budget;
- then `msr_prn_0` at 1M requests for 0/1/5/10/20 ms;
- report effective HR, resident C/P HR, delayed/coalesced rate, AAT, demand I/Os, prefetch I/Os, backend bytes, and latency saved per prefetch I/O/byte.
